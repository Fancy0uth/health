- Candidate staging cannot write facts. Read-source/context prerequisites required before W1/W2/W3 extraction; continuation reads confirmed instructions. Fact/source dependencies must actually have been retrieved/read, not merely guessed. Context supports normalized literal query, source evidence and assigned episode filters. No arbitrary shell/file/network tool is exposed.
- Export is owner-only and includes originals as base64. Deletion actually removes active local rows/BLOBs and dependent text, revokes scopes, retains minimal opaque receipts/tombstones and request hashes. A deleted source request cannot replay into recreated data. Status is always partial because AGH traces, backups and storage remnants cannot be certified erased.
- PDF uses locally installed fixed-path Poppler via argument arrays, bounded output/timeout, private random tempfile and cleanup. Corrupt/scanned/mislabeled/oversized documents have explicit errors. No OCR/audio/clinical triage thresholds. D01/D02 remain not_configured.

### Root causes and fixes

1. **Borrowed candidate semantics** — reproduced `头痛。诊断肺炎。`, rendered value `头痛。`, field diagnosis, both quoted sentences; similarly reproduced borrowed negation/past/time. Candidate evidence must now *all* equal the rendered value. Field/assertion/temporal/effective-time validation reads the rendered value only; unrelated auxiliary evidence rejects. Reused confirmation validation has the same constraint. Explicit mixed-evidence regression went red then green.
2. **Concern quote laundering** — reproduced history-only speech with one claim carrying history + unused concern evidence. Every evidence quote and referenced fact value must equal that claim's rendered text; concern coverage requires matching source *and rendered quote*. Separate rendered history and concern claims remain valid. Regression asserts rejection leaves no result, then the two rendered claims succeed.
3. **Hidden W3 instructions** — reproduced one task rendering the first instruction while referencing both distinct instructions. Every task reference must now have the rendered task text; completeness also checks actual rendered text and revision. The regression demonstrates distinct actions reject when merged and succeed as two tasks. Genuine identical instruction texts are allowed to share one task with both refs.
4. **Stale-review dead end** — explicit rejection now compares `expected_profile_revision` to current profile, not old proposal base, and changes no facts. New `reanalyse(uid,runId,{expected_profile_revision},key)` and POST `/api/runs/:id/reanalyse` atomically validate current owner/consent/profile/source, expire old proposal, cancel old scope, create a new run/outbox referring to unchanged saved sources. HTTP also aborts the superseded worker's wait. Stale confirm still 409. Tests cover CAS failure rollback, cross-owner rejection, same-key replay/conflict, old callback refusal, no duplicate entries and successful fresh review. New OpenAPI endpoint includes explicit typed ReanalysisReceipt.
5. **Uncaught SQLite claim errors** — real two-connection SQLite `BEGIN IMMEDIATE` reproduced escaping `kick()`. Scheduler now contains claim and task-rejection exceptions, preserves queued records, emits sanitized code/request/phase diagnostics, retries with finite exponential backoff, then suspends. Defaults: 3 attempts, 250 ms base, 5000 ms cap. `/api/health` stays live and reports `dispatch`; `jobs.status()` exposes the same status. Operator `jobs.resume()` or service restart recovers; unknown in-flight effects become interrupted or preserve checkpoint with execution_error rather than replay. Scope tools bound to the worker signal reject after it aborts. Diagnostics never include raw SQLite messages/paths/source text. The timer regression waits for a real diagnostic event, then verifies HTTP health/source/operation still work during lock and resume after unlock. A clock-controlled test verifies retries stop at the bound and restart processes the durable queued source.
