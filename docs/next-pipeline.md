# 共享骨架后的实施顺序

1. B 实现用户身份、来源对象和字段级事实 Schema；C 与两端对齐候选、证据、版本和确认协议。
2. C 实现 AGH 插件 read_source、retrieve_health_context、stage_candidates；B 为每次运行签发受限访问范围。
3. 完成 W1：服务端先存原文，AGH 实际读来源、检索、提取、校验，前端核对，后端提交；逐步替换 /api/state 整体保存。
4. 完成 W2：使用有效历史和用户选定记录生成表达稿、问题清单及来源；事实更正后使依赖产物过期。科室策略单独按 PRD D01 决议实现。
5. 完成 W3：保存文件与文本，处理 PDF、字段出处、差异核对、事务提交，再根据已确认医嘱生成多条事项。
6. 双端验收：手机录入、电脑读取；电脑更正、手机显示新版本与过期卡；取消和删除后的旧响应不恢复资料。
7. 用 12 条开发和 12 条留出合成案例评估，保存真实 AGH 工具回执和版本；明确演示、fixture 与真实执行的区别。

当前所有运行记录和资料只供合成演示。正式删除必须覆盖业务资料、派生物、缓存和适用 AGH 轨迹；不能把 /api/state 中的空档案当作完整删除证明。
