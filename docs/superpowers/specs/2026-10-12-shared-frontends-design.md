# HealthThread 双端与共享后端设计

本次按用户已确认的接入架构实施：电脑版和手机版保持独立应用，共用业务服务与接口契约，模型执行统一通过主办方 Agnes Harness 和 Agnes 模型。用户本轮明确要求完成组织调整并上传现有 GitHub 仓库，因此连续完成实施、验证和上传。

## 交付范围

- 从两份上传 ZIP 分别导入桌面界面和手机界面，保留布局、素材和已有交互。
- apps/web 和 apps/mobile 独立维护；移除手机对桌面源码目录的依赖。
- packages/client 承载公共 API、原有合成资料及共享状态适配；contracts 承载协议说明。
- services/api 提供同源静态服务、SQLite 共享状态和真实 AGH SDK 接入边界。
- 本期共享状态保留既有原型数据结构；正式字段级事实确认、账号系统和三个受控 Agent 工具工作流另列后续任务，不能宣称本次已完成。
- 没有 AGH 配置时明确返回 AGENT_NOT_CONFIGURED，不能用本地模拟回复冒充 Agnes 调用。
- AGH 作为独立第三方运行时，SDK 通过公开包入口消费，密钥只由 AGH 管理。

## 数据与可靠性

一个明确的合成演示档案由后端保存；浏览器只保留缓存、草稿和偏好。共享状态写入附 expected_revision，冲突不覆盖服务端新值。后台读取用于双端同步，保存失败保留本地草稿并提示。删除须通过后端产生可同步的空档案，不自动补回模拟病历。

## 验收

两端页面及所有模块和素材路径可访问；两端读写同一档案；服务重启后保留数据；旧 revision 写入被拒绝；未配置 AGH 时 AI 请求明确失败；SDK 适配只接收真实会话结果；取消不伪造完成。已有视频项目不加入本次提交。仓库目标沿用 origin：Fancy0uth/health，目前为空且私有。
