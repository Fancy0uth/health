# 持续维护的身体状态文档

用户目标：Agent 按 Project Framework v0.2 第四章的“问题事件＋时间＋证据”范式，结合自述、病历记载及后续反馈维护结构文档，对当前身体情况作有依据的信息评估，直观展示整体近况。现有摘要和部位卡片不足以表达这个理解。

## 范围与关系

扩展现有健康概述流水线，复用 health_overview 的不可变快照、运行核验、来源权限、版本与失效保护。模型负责组织和更新完整文档；服务端负责保存、来源/版本核验与生命周期；前端只呈现。聊天、整条记录修改、文档分析、差异解决及反馈均使用同一结构。保留旧 summary/regions 读取和公共工具兼容性，不能把历史卡片直接拼接冒充新模型评估。

## 模型文档 v2

overview 的新形式：`{format_version:2,summary,problems,background,uncertainties}`。
- summary：1–3 句近期整体情况，最多 1200 字；实际生成建议 2–3 句、不超过 200 字，重点说明最近主要不适、已有依据的变化和关键未知，不罗列全部原文或处理元数据。
- problems：最多 30 个有依据的问题事件，每项 `{key,title,body_region,status,assessment,dimensions,source_ids}`。key 是不超过 80 字符的稳定问题标识；模型对照上一版复用，确实新问题使用新 key。body_region 使用已有七个部位 ID。status 为 active/improving/resolved/uncertain，表示仍关注、好转、已结束、未澄清，不能当疾病严重程度。
- assessment：最多 600 字，模型依据资料解释该问题目前怎样、与前次相比怎样、仍不确定什么。只能描述有来源支持的变化，不能诊断、排除风险、改药或捏造健康分数。
- dimensions：八个键全部存在，每个值为最多 800 字的简短综合或 null：body_site_symptom、time_course、self_rating、impact_context、associated、measurements、background_care、evidence_status。对应第四章八维；null 表示未记录/不清楚，绝不等于没有。明确否认保留时间范围；自评分标明用户自评；指标保留单位和原日期；病历判断按资料归属，不由症状推出诊断。
- source_ids：非空，只引用本轮实际读取、当前账号授权的原始资料。上一版文档是模型理解上下文，不是新的事实证据；不得以助手消息或被整条修改替代的旧资料支撑当前判断。
- background / uncertainties：各最多 30 项 `{summary,source_ids}`，每个 summary 最多 800 字、来源非空。分别是相关用药/过敏/既往/病历结果与重要未知或矛盾。保留待核对两方，不自动选定胜者；医嘱计划与实际执行分清。

新文档完整替代上一版。仍在关注且来源有效的旧问题不能因本轮未提到而静默消失；要求同 key 留在新文档。已结束问题可退入版本历史，整条修改明确替代的旧问题可重新组织。任何此保护的例外必须针对真实失效/替代来源，不能靠模型自称已解决绕过。服务器保存 document_version、framework、previous_document_id、profile_revision、来源及运行依据，不生成医学内容。

## 自动维护与现有数据

工具上下文明确提供上一版结构文档、当前事实/原件、事件和证据状态。活跃模型的 overview schema 与技能明确使用 v2；公共旧格式仍兼容。新增资料的自动记录完成即保存新版本；差异处理沿用 overview_refresh。
增加幂等 POST `/api/health-profile/refresh`（operation_key）：只创建已有 entry 工作流的 overview_refresh，不提取/确认新事实。当前账号有分析同意和可用资料才可运行；已有运行返回同一运行；无资料明确返回无记录。手动刷新或旧概述首次进入页面时升级，同一次失败不自动循环重试。按已有运行重试与失效逻辑处理，失败保留旧文档并明确显示未更新。刷新无 overview_change_id 时不能读取不存在的差异记录。

## 页面

依用户最新反馈，电脑与手机主视图改成一页直接阅读的近期汇总：先展示模型生成的整体近况，再按第四章八维直接呈现有记录支持的简短综合。不同问题保留名称与归属；重复文字合并呈现；相关背景并入“背景与处理”；由模型集中说明重要未知，不列缺失维度清单。没有内容的维度不显示空卡片，前端不补充健康判断。旧资料保留原时间；缺乏近期更新时，模型明确内容截至最近记录。

去掉身体近况页的记录/来源/差异视图切换和逐问题八维折叠卡；原始资料统一放在“查看汇总依据”，同一出处仅提供一个链接。已结束问题另行收起。保留更新时间，隐藏内部文档版本与状态键。健康时间线“身体记录”下的身体近况按钮在两端删除；首页入口保留。自动更新仍使用原流水线，手动按钮为“更新汇总”；失败时只展示对应运行的重试入口，避免将已失败任务再次当作新评估请求。
旧格式不假装已经完成新评估，首次进入有资料且已授权时自动升级；更新/失败状态与一键重试可见。保留 >=44px 操作区域、两端布局、展开状态与刷新稳定性。

## 验证

域测试覆盖完整八维与权限、旧问题连续维护、整条修改去旧、快照版本、失败不覆盖、刷新幂等/同意/无资料/并发旧结果；真实 SDK 活跃原生对象结构；两端渲染转义、空值不写正常、重试与折叠。真实 Agnes/browser 合成场景：上腹不适→补充程度/影响/否认→膝盖新问题仍保留上腹→病历评估/测量/医嘱→实际改善反馈→整条更正；检查文档和界面更新及来源。不得使用模拟模型通过冒充真实模型验收。
