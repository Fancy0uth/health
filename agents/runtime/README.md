# Controlled HealthThread AGH runtime

Node 24.10+ is required. From the project root run `npm run build:agh-runtime`, then `npm run verify:agh-runtime` (no inference), then `npm start`. `npm run verify:real-workflows` uses synthetic data in a separate ignored database and the genuinely configured Agnes provider; it makes real model calls. `node --test tests/agent/*.test.mjs` uses an explicitly labeled scripted provider through the genuine public Host and SDK.

The builder reads `AGH_ROOT` (or the machine default checkout) `/Users/fancyouth123/Documents/Codex/2026-10-06/https-github-com-agnesai-labs-agnes/work/agnes-harness` and its already-installed dependencies. It requires the exact commit in `agents/harness.lock.json` and no tracked source changes. It writes `.runtime/agh-dist/runtime.mjs`, SHA256 provenance, upstream Apache license and attribution. No source checkout or global daemon changes occur. It packages public Host, SDK, daemon/local, base, ai, package manager and resource registry; generic/native tools are never admitted.

Credentials remain protected SecretRefs in `AGH_ACCOUNT_HOME` (legacy alias `AGH_HOME`), defaulting to the existing `/Users/fancyouth123/Documents/Codex/2026-10-06/https-github-com-agnesai-labs-agnes/work/agh-home` profile `AGH_ACCOUNT_PROFILE` (default `local-dev`). The backend reads its public ConfigurationService status/profile inputs, requires `agnes-ai`, and selects the exact configured account route/model. It neither copies secrets nor puts credentials/configuration into prompts, browser payloads or logs. Set up the existing account using its supported AGH configuration workflow if status is unconfigured. The runtime does not invent a credential or silently select another provider.

The deployment home is `<HEALTHTHREAD_AGH_HOME>/releases/<approved-assets-hash>`, with the owned base defaulting to `.runtime/agh-home`. Existing/symlink-resolved account and source roots are protected against runtime writes. Build/verify npm scripts load `.env` if present; credential values still belong only in the external protected account configuration. A changed approved plugin/Skill revision produces a distinct deployment and retains prior trace generations. The package manager actually inspects, installs, trusts the inspected integrity/capability hash, enables, and active-pins `@healththread/runtime`. The source manifest rejects unreviewed files, symlinks and changed bytes. New source revisions require reviewing and updating this manifest, then reinstall through a new generation; editing installed assets is rejected. Only the newly authored standalone plugin files are MIT; see plugin/LICENSE and NOTICE. Other repository code/data licenses are unchanged.

Skills are copied from exactly four reviewed files into the owned workspace `.agh/skills`. A real SkillCandidateRegistry discovers only that root, explicitly controls revision trust/enabled state, activates and checks readiness. Ambient home/project roots are never scanned. Requests preload the correct real Skill and server IDs only. Source text arrives only via bounded business tools as untrusted data.

Actual registry names, package provenance and definition fingerprints are verified and frozen. Actual provider requests must contain exactly the same five tools, configured route/model and preloaded Skill. Background title requests fail this same boundary before inference. No shell, files, web, notebook, MCP, generic helpers, subagents, writable configuration or package-management tools are present. Eight trusted Core seams provide approval/principals/artifacts/checkpoint/ledger/verifier/repair/harness mechanics, not extra callable tools. The private in-process endpoint composes genuine public Host → daemon/local → SDK.

The adapter reserves and durably binds an opaque session key, then checks scope on every tool. SDK session identity, actual tool-use IDs, canonical argument hashes and readToolDetail event sequences must all agree with persisted receipts. An exact stage replay receives its own SDK invocation correlation referencing the original tool-use ID and matching original operation/request hash/outcome; the queue gets each persisted effect receipt once in original order. Assistant JSON cannot create output. Internal verifier repair is disabled; at most two shared local repairs include Core schema errors. The repaired-checkpoint acknowledgment may consume the remaining repair and forbids all tools. Step limit 12, no subagents, no compaction, unchanged credit defaults and existing 120-second domain deadline apply. Abort cancels the real session and revokes scope before late effects.

Readiness/configuration failures preserve accepted original data and leave model runs explicitly blocked. Valid checkpoints followed by SDK failure retain their payload and execution_error. AGH traces may contain source data; deletion truthfully marks trace erasure unverified rather than claiming secure deletion. Synthetic evidence and old generations remain under ignored `.runtime`; do not publish them or treat fixture results as real model quality evidence.

Each business run opens a separate private Host, local endpoint and SDK client in a unique owned `runs/<id>` subdirectory of the deployment home. The shared readiness runtime never acquires business sessions. Supported client.close, endpoint.close (including SessionRegistry.closeAll/listener/tail disposal), and Host.close run before the per-run handle is dropped. There is no direct mutation of upstream session maps. Concurrent runs have separate permission routing, Skills/binding closures and clients; shutdown waits for both active and opening connections. Trace files remain on disk for the existing explicit retention/deletion policy. A provisional startup runtime is published only after its final isReady succeeds; failure closes it and leaves capabilities not_configured.
