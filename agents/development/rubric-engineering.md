# 评分导向的后端工程与验收要求

提示词包修订版 v0.2，2026-10-12。评分项和权重由用户在对话中提供；本文件没有另行核验官网，也没有把下列工程门槛说成官方评分细则。PRD 和当前代码的能力边界仍然有效。

## 一、评分项 → 代码工作 → 证据

| 评分项 | 权重 | 实施侧重点 | 交付与验证证据 |
| --- | --- | --- | --- |
| 技术深度与系统实现 | 25% | 服务端事实真相、来源/版本模型、事务、持久化任务、幂等与隔离；两端统一 API，AGH 工具受限 | 架构与关键 ADR、实际 schema/迁移、原子提交/并发/重启测试、跨端动作；解释失败时仍成立的不变量 |
| 验证严谨性与异常处理 | 20% | 可注入故障、状态机、取消/恢复、失败透明、资源限额；独立测试与复核 | 故障矩阵、每场景复现与断言、测试命令/环境/结果、恢复前后 DB/回执、未覆盖范围 |
| 任务完成度与结果正确性 | 15% | W1/W2/W3 全链路、逐字段真实来源、保留未知/否定/不确定、两端每动作完成 | 需求到代码/测试映射、冻结样例及实测指标、真实两端验收、实际成功与失败结果 |
| AGH 与模型执行闭环 | 15% | 实际 session/tool steps、受控业务回执、确认接续；所有模型槽 Agnes | session/seq/工具回执→候选→用户确认→事务回执→UI 的证据索引，版本/模型/预算与终态 |
| 问题价值与学科融合 | 15% | 用户把零散资料转成可追溯、可更正的就诊沟通材料；健康信息管理与软件治理结合 | 手机到电脑的实际用户旅程、更正后卡过期、出处查看、减少整理步骤的测量与边界；不虚构临床效果 |
| 创新性与发展价值 | 10% | 围绕已运行闭环的可追溯事实更新、资料变化使派生物失效、人工确认机制与扩展边界 | 可工作的差异与依赖模型、小型对照实验、明确当前能力/可扩展接口；不以堆框架、Agent 数量或 TODO 替代实现 |

技术实现与异常验证合计 45%；加上任务正确性和 AGH 闭环合计 75%。此比例用于开发优先级，不要求按百分比分配代码量或用测试数量计算比赛得分。

每个关键模块同时交付：成功路径、失败路径、恢复路径、可观察证据。先保住关键不变量和三工作流闭环，再扩展功能；必要的架构深度来自真实边界与测试，单进程 Node+SQLite 也要把这些边界做好。不为得分引入微服务、Kafka、向量平台或更多 Agent。

## 二、不得被吞掉的不变量

| 编号 | 不变量 | 必须检查的观察点 |
| --- | --- | --- |
| I01 | 正式事实写入只能由服务端验证后的用户确认事务产生 | Agent 工具调用前后事实 DB 的有效版本；不能工具自行确认 |
| I02 | 保存回执与真实持久化一致；分析失败不丢已保存原文 | HTTP 回执、重启后 source/entry、原文/hash |
| I03 | 来源/原文保留语义，确认不暗改输入或抹除旧版 | 原文及版本、否定/时态/未知/模糊时间、原始医嘱 |
| I04 | 同一用户/操作/key 相同 body 至多一次业务提交，不同 body 拒绝 | 幂等回执、事实版本数、重复请求与丢响应后查询 |
| I05 | 版本检查、确认、审计/回执、依赖失效在同一业务事务中 | 两端竞争、事务中途失败、当前/旧卡版本一致性 |
| I06 | 身份、授权和 tool scope 每次由服务端核验，模型 ID 不授予权限 | 各类对象的跨账号 read/update/export/delete、scope TTL/撤回 |
| I07 | 取消/删除/撤回后旧 epoch 的任务不能产生新的有效业务写入 | 工具开始时/写事务内/结果提交时的检查；迟到 callback 和 UI |
| I08 | completed 只表示对应阶段产物已验证持久化；202 不表示完成 | run/result 终态、结果所属阶段、部分成功与副作用回执 |
| I09 | 事实更正/撤回/删除后依赖的卡/事项不能仍被当作当前资料 | source/fact revision 依赖、stale/withdrawn、两端视图 |
| I10 | 内部错误、模型密钥、管理凭证和他人资料不泄露 | HTTP body、日志、静态目录、tool args/result、导出/截图 |
| I11 | 重试有界，副作用未知不能盲重放，重启不伪造成功 | 传输/业务/局部修复计数、run 检查点、operation receipt |
| I12 | 真模型与 fixture、实际工具回执与模拟事件严格标识 | runtime=fixture/real、AGH 日志来源、版本/模型；不合成真 trace |

“异常处理完美”以这些已定义不变量和故障场景的测试为目标。只能报告“指定矩阵全部通过、仍有这些未测边界”，不能把有限测试宣传成零故障保证。

## 三、必须设计的工程边界

1. **持久化接收与派发。** 原文文本或已核验持久化的文件引用、Entry、Run 和待派发记录在同一 SQLite 事务形成可恢复回执；可以采用小型 outbox/持久化任务表。文件系统用受控暂存/持久化/事务关联与孤儿回收处理其独立边界。AGH 调用在事务外。数据库与文件系统/远程 AGH 不是分布式原子事务，不能声称全局 exactly-once；依靠业务幂等、版本检查、状态 CAS 和回执处理未知结果。dispatch 失败后已存原文仍在，run 明确 blocked/failed/interrupted，可按回执恢复。
2. **合法状态转换。** M0 冻结 transition 表、终态、取消可作用阶段、needs_review 接续和副作用说明。用条件写入/CAS 拒绝过期 worker 与非法转换；用户确认检查点落库，不占工作线程等待用户。中断后原 run 的历史状态保留，重试/接续引用原始输入和回执，不随意把 cancelled 改 completed。
3. **事务和资源。** 写事务短、批量参数化 SQL；锁冲突重试有界、超时回滚。确认事务同时核验来源/授权 epoch，删除/撤回事务改变同一可串行裁决的版本；区分已经提交的效果与后来被撤回的效果。临时文件、解析线程、连接、轮询/计时器和 session 在失败/取消/退出时清理；CPU 密集 PDF 解析不能仅用一个不会中断同步工作的 AbortSignal 声称有超时保障。
4. **限额和背压。** 为输入字节数、上传大小、检索条数、queue depth、全局/每用户并发、工具/模型/解析 deadline、输出长度、重试/修复/credits 设可配置限制。单名用户不能占满工作队列。M0 明确拒绝发生在保存前还是后；保存前拒绝不能显示已保存，保存后无法分析必须返回已存对象和真实状态。超限、429、超时不伪造 empty-success。
5. **错误契约。** 统一稳定 code、公开 message、request_id、阶段/已存对象/是否可重试；所有路径都可区分输入不合法、权限拒绝、版本冲突、未配置、不支持、依赖失败、中断、部分完成。未知内部错误应安全返回 5xx 并记录关联 ID，不能 catch 后返回成功或只 console.log；不能为了稳定吞掉错误。
6. **可观察性。** 记录 request_id/run_id/operation_id、真实 AGH session/seq、阶段耗时、状态转换、校验错误、重试计数、queue wait、取消与清理结果；日志不默认记录健康全文/凭证。可鉴权查看的业务审计与脱敏运维日志分开。liveness 不代替 readiness；数据库/AGH/工具/Skill 未就绪时 capability 与运行状态真实反映，未配置不自动切其他模型。
7. **验证来源支持。** schema 校验、真实 source version/quote/区间、事实时态/否定/不确定性、允许字段/医嘱范围分别检查。模型自评不作证据。遇到支持不明则 pending/拒绝，重要项人工核对；用户勾选确认不能绕过明显的错引或权限错误。

所有上述行为都要有实际 owning module、测试和恢复操作；没有必要的实现就标缺口，不用抽象接口名称代替。

## 四、故障矩阵（必须由实现与独立测试共同覆盖）

每行登记 owner、输入与注入点、预期 HTTP/run/UI/DB、已提交效果、恢复操作、自动测试路径/命令、执行结果和证据。相同矩阵逐阶段补齐，不能只在最后写一份错误文案。

| ID | 故障或边界 | 必须成立的结果及恢复 |
| --- | --- | --- |
| E01 | 空/畸形 JSON、异常类型、超限文本、非法 ID | 明确拒绝，无未预期写入；两端保留可编辑草稿，不显示已存 |
| E02 | session 过期、账号切换、猜测 source/run/result/task/export ID | 拒绝/防枚举，无他人数据；注销/切换清掉旧账号视图，旧草稿不发给新账号 |
| E03 | 文档提示注入、伪造 user_id/token/URL/path、过期/越权 scope | 文档不能改变权限；无额外工具/外网/文件动作；拒绝回执明确 |
| E04 | DB 未就绪/写失败、锁超时、迁移中途失败 | 回滚或保留已提交效果，不能假保存；有界重试/明确 5xx，迁移可检查恢复 |
| E05 | 原文事务提交前/后进程退出，派发失败 | 原子回滚或完整接收记录，重启仍能定位 source/run；不成为有原文无处恢复的孤儿 |
| E06 | 已存输入的 HTTP 回执丢失、相同 key 重发、key 换 body | 同 body 得同对象/回执，无重复 source/run；换 body 拒绝；先查回执 |
| E07 | AGH 断开、模型未配置/凭证失效、provider 不符 | 原文保留，分析状态真实；不切非 Agnes/模板成功，凭据不泄露 |
| E08 | 模型/工具超时、429/预算耗尽、暂存结果回执未知 | 有界恢复；副作用未知先查 operation receipt，不盲重放写入；无无限轮询/重试 |
| E09 | JSON 错、被截断/streaming/lostChars、输出超长/字段缺失 | 无完整结果假象；局部修复总数最多 2，仍失败原文保留；支持人工处理 |
| E10 | quote 存在但不支持字段，否定/既往/考虑被改，缺剂量/无时间锚 | 字段校验拒绝/待核对，未知保持；不得提交错误有效事实/添医嘱 |
| E11 | 手机与电脑同时确认相同旧版本 | 一个事务成功，另一 409；回执/版本/依赖更新一致，冲突端保留选择并刷新 |
| E12 | 确认事务中途失败，或确认成功后 HTTP 响应丢失 | 全回滚或完整提交；同 key 可取同 commit receipt，版本不重复增加 |
| E13 | 服务在 queued/running/needs_review/确认接续时重启 | 持久化阶段和输入保留，运行者按策略 interrupted；检查点不丢，恢复不双写 |
| E14 | cancel、授权撤回、删除与模型/tool callback 并发 | 取消后的新写拒绝；已提交效果有回执，撤回/删除语义明确；旧 UI response 不恢复数据 |
| E15 | 更正/撤回/删除所依赖事实，选入过期/他人历史 | 所属校验、有效版本检索；旧材料 stale/withdrawn，不悄悄改事实或继续显示当前 |
| E16 | 非 PDF 冒名、损坏/加密/无文本 PDF、解析超时/取消、临时文件异常 | 明确 unsupported/failed，原文件处理状态可查；解析资源/临时文件清理，不能伪造正文 |
| E17 | 高于已定队列/并发限额，一个用户大量提交 | 背压与隔离生效，其他用户仍可服务；按冻结规则拒绝/等待，不能无界创建 session |
| E18 | 浏览器断网、轮询失败/过期、未失焦草稿、旧 fetch 晚返回、刷新 | 状态可恢复，草稿不抹掉/静默重放；poll 有 deadline/backoff/cancel，不误显示完成 |
| E19 | XSS 文字、CSRF/错误 Origin、访问静态 .env/DB/病历路径 | 转义与授权边界成立；无脚本执行/资料静态暴露，不只靠前端隐藏按钮 |
| E20 | 导出/删除期间文件/索引/AGH 轨迹层失败，删除回执丢失 | 各层回执真实，partial/pending 不能写完全成功；重试继续同一 job，不删他人数据 |
| E21 | Skill 未 ready、插件禁用/卸载、SDK 版本不匹配、stage metadata 不符 | 依赖错误明确、能力不假就绪；禁用清资源，副作用不自行回滚；不放宽版本/权限检查 |
| E22 | W3 无医嘱、仅部分字段确认、多事项与任务更新冲突 | 未确认/含糊内容不变正式事项，tasks 可为空；状态更新带版本，反馈走新记录 |

故障注入只在测试依赖适配器、临时 DB/文件/实例里进行；生产接口不能接受 force_error、任意延迟、删除 DB 等测试开关。并发测试使用可控 barrier/时钟/随机种子，不依赖碰巧发生的 sleep race。单元 fixture 可演依赖故障，进程重启与双端任务另做真实 HTTP/持久化集成验证。

## 五、指标、对照和证据

- **不变量/确定性故障门槛：** I01–I12 和适用 E01–E22 的已定用例全部通过；未测、不支持注入或只有手动证据分别标识，不能算自动通过。越权、非用户确认写库、重复提交、误事实生效、删除后恢复资料、伪真轨迹任一可复现则阻断 MVP 验收。
- **模型质量：** PRD 的 12 开发/12 留出是模型评估集，不代替故障矩阵。记录每例字段预期、来源支持标签、未知/否定/时态、workflow completion 与局部修复；报告分子/分母、失败例、实际模型/prompt/schema 版本。字段准确率、来源支持率、状态正确率分开；不得用“JSON 合法率”代替结果正确率。PRD 的建议数值仍须明示为项目建议，不能称比赛官方阈值。
- **复现与性能：** 记录设备/Node/SQLite/AGH 版本、并发值、输入规模、queue wait、各阶段耗时与成功/失败/取消数。样本足够才报告分位数；少量真实调用列逐次数据，不编 SLA、成本或性能数字。门槛在 M0/D09 定稿，测不达标就改/限流/降级并披露。
- **发展价值的最小对照：** 在同一批开发合成输入上，对比固定的“仅 prompt 输出、无来源/版本治理”基线与受控工作流；观察错引是否被发现、修复是否越界、旧卡是否正确过期、异常是否保原文/防重复。写明额外步骤/延迟/成本，基线与新方案均固定版本。留出集冻结后才运行；不能看答案再宣称改善。
- **证据包：** docs/backend/score-evidence.md 按六项列具体代码、测试和可复现演示；docs/backend/fault-matrix.md 对应每个 E；invariants.md、state-transitions.md、verification.md、ADR、evals 报告、脱敏 trace 索引。证据有 head SHA、命令、退出码、数据/seed、时间和边界；截图辅助，不替代 DB/回执/实际轨迹。

演示至少包括：手机录入→电脑核对、事实更正→旧卡过期、真实病历→确认→多事项、模型失败但原文仍在、双端冲突不覆盖、取消/删除后晚结果不恢复。每个用户结果都能沿来源与 run/commit 回执解释，不能只展示会聊天。

## 六、评审门槛与职责

- M0：总控冻结六项证据计划、不变量、状态转换、输入/队列/时间/重试限额、错误/恢复契约和 E 场景 owner。
- M1/M2：Data/API 与 Workflow 实现后，Reliability/Test Agent 依据契约写独立故障测试，落实 W1/确认/取消/重启的通过证据；不让测试作者改业务代码迎合断言。
- M3/M4：补足 W2 依赖失效与 W3 文档/医嘱/接续故障，进行第二次独立复核。
- M5/M6：双端故障验收、全关键矩阵、模型开发/留出和真实 AGH 轨迹；独立 Review 审查最后 diff 和证据。发现问题由 owning implementer 修复，保留失败→修复→回归的证据。

Reviewer 在 M2、M4、M6 轮换参与，不需要常驻占槽。总控仍最多两个子任务；测试 Agent 不再派生。已通过且未受新变更影响的检查不用重复消耗时间/模型额度。不能因异常验证加严而无限扩展产品范围，D01/D02 未决分支保持关闭且明确未实质验收。
